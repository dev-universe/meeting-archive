# 회의 보관함

Windows에서 녹음 파일을 끌어놓으면 한국어로 전사하고, 녹음 날짜가 붙은 폴더에 녹음본과 TXT를 함께 보관하는 데스크톱 앱입니다. 전사는 이 PC의 NVIDIA GPU에서 실행됩니다. API 키와 건당 전사 비용이 필요하지 않습니다.

## 새 Windows PC에 설치

**RTX 3060 Laptop 6GB에서는 현재의 `int8_float16` 설정을 사용합니다.** RTX 3050 6GB에서 실행을 확인한 구성이고, 3060 Laptop에서의 속도·VRAM 사용량은 아직 실측하지 않았습니다. 노트북 전원을 연결하고, 메모리가 부족하면 Turbo를 선택하거나 다른 GPU 프로그램을 종료하세요.

준비물: 64비트 Windows, NVIDIA GPU와 최신 호환 드라이버, 인터넷, 모델과 두 Python 환경을 위한 충분한 디스크 공간. RAM은 16GB 이상을 권장하며 긴 회의의 화자 분석에는 더 필요할 수 있습니다. CUDA Toolkit과 별도 Python을 직접 설치할 필요는 없습니다.

1. 이 저장소의 **Code → Download ZIP**을 눌러 다운로드하고, 쓰기 가능한 폴더에 **압축을 모두 풉니다**. 또는 Git으로 복제합니다. 동기화 폴더보다 로컬 폴더를 권장합니다.
2. Windows 터미널에서 아래 명령으로 uv를 한 번 설치합니다. [uv 공식 설치 안내](https://docs.astral.sh/uv/getting-started/installation/)

   ```powershell
   winget install --id=astral-sh.uv -e
   ```

3. 터미널을 닫고 압축을 푼 폴더의 **`install.cmd`를 더블클릭**합니다. Python 3.11, 전사 환경, 화자 분석 환경을 설치하고 GPU를 점검합니다. 최초 설치에는 큰 패키지 다운로드로 시간이 걸립니다.
4. 설치 완료 후 **`start.cmd`를 더블클릭**합니다. 이후에는 이 파일로 바로 실행합니다. `start.vbs`도 사용할 수 있습니다.
5. Whisper 모델은 선택한 모델로 **처음 녹음을 전사할 때 자동 다운로드**합니다. 일반 전사는 Hugging Face 가입이 필요하지 않습니다.
6. 화자 구분은 앱의 **모델 준비**에서 아래의 Hugging Face 절차를 진행합니다. 이미 같은 계정으로 모델 접근 조건을 수락했다면 새로 가입할 필요 없이 해당 계정의 읽기 토큰을 사용합니다.

**GitHub에는 프로그램 코드만 들어 있습니다.** 이 PC의 가상환경, 모델, 토큰, 녹음, 전사본, 설정·작업 기록은 포함하지 않습니다. 노트북에서도 모델 준비를 한 번 완료해야 합니다. 모델 다운로드가 끝나면 로컬에서 처리하며 녹음 파일을 전사 API에 업로드하지 않습니다.

`install.cmd`의 실행 정책 지정은 해당 설치 프로세스에만 적용됩니다. Windows 실행 정책을 영구 변경하지 않습니다. 설치가 실패하면 창의 오류를 확인한 뒤 해결하고 다시 실행할 수 있습니다. 설치 폴더를 나중에 옮기면 가상환경을 다시 만들어야 할 수 있으므로 처음부터 사용할 위치에 압축을 푸세요.

## 실행

설치 후 **`start.cmd`를 더블클릭**하거나 프로젝트 폴더에서 아래 명령을 실행합니다.

```powershell
.\.venv\Scripts\python.exe run.py
```

1. 저장 위치를 확인합니다. 기본값은 설치 폴더 아래의 `output`입니다.
2. 모델을 선택합니다. Large v3는 정확도 우선, Turbo는 속도 우선입니다.
3. 녹음 파일을 창에 끌어놓거나 **파일 선택**으로 여러 파일을 추가합니다.
4. 기본 설정에서는 바로 전사를 시작합니다. 결과 행을 선택해 **결과 폴더** 또는 **TXT 열기**를 누릅니다.

```text
output/
  2026-09-08_03-30-45_주간회의/
    주간회의.m4a
    주간회의.txt
    metadata.json
```

원본은 유지하고 결과 폴더에 바이트 그대로 복사합니다. 동일한 날짜·이름이 이미 있으면 `_02`, `_03` 등을 붙여 기존 결과를 보존합니다. 대기 중이거나 처리 중인 같은 파일을 다시 추가하면 한 번만 처리합니다. 이미 완료된 파일을 다시 추가하면 새 결과 폴더를 만듭니다.

지원 형식: M4A, MP3, WAV, FLAC, OGG, OPUS, AAC, WMA, MP4, MOV, MKV, WEBM, AMR, 3GP, AIFF. 동영상은 첫 번째 오디오 트랙을 전사합니다. 폴더 자체를 끌어놓는 기능은 없습니다.

## 6GB GPU의 모델 선택

직접 확인한 GPU는 **RTX 3050 6GB**, 드라이버는 596.49입니다. 기본 구성은 `faster-whisper`, `large-v3`, `device="cuda"`, `compute_type="int8_float16"`, 한국어 고정, beam size 5, VAD 켜기입니다. 파일을 순차 처리하며, 대기열이 끝나면 GPU 프로세스를 종료해 메모리를 반환합니다.

Whisper는 모델이고 faster-whisper는 그 모델을 실행하는 구현체입니다. faster-whisper 공식 문서가 CUDA에서 INT8 실행을 지원하므로, 6GB GPU에서 먼저 시도할 합리적인 조합입니다. 공식 표의 메모리 수치는 Large v2 / RTX 3070 Ti 기준이므로 이 PC의 Large v3 실측치로 해석하면 안 됩니다. [faster-whisper 공식 문서](https://github.com/SYSTRAN/faster-whisper)

Turbo는 Large v3의 디코더 층을 줄여 속도를 높인 모델입니다. 일부 품질 저하를 감수하는 선택이며, 한국어 회의에서의 차이는 실제 녹음으로 비교해야 합니다. 영어 중심의 `distil-large-v3`와는 다른 모델입니다. [Turbo 모델 카드](https://huggingface.co/openai/whisper-large-v3-turbo)

VibeVoice의 전사용 제품은 **VibeVoice-ASR**입니다. 기본 ASR 모델은 화자·시간·내용을 함께 출력하고 60분 입력을 지원하지만, 이 PC의 6GB VRAM에 기본 BF16 모델을 온전히 올리기에는 큽니다. 이는 모델 규모에 근거한 판단이며 이 PC에서 VibeVoice를 직접 실행한 결과는 아닙니다. [Microsoft 공식 저장소](https://github.com/microsoft/VibeVoice), [ASR 모델 카드](https://huggingface.co/microsoft/VibeVoice-ASR)

2026년 9월 확인 기준으로 **VibeVoice-ASR-BitNet**도 있습니다. 공식 문서상 약 1.58GB의 CPU용 모델이며 한국어를 포함합니다. 따라서 모든 VibeVoice 모델에 대형 GPU가 필요하다고 볼 수는 없습니다. 다만 Windows에서는 별도 C++ 빌드가 필요하고, 이 앱에는 통합하지 않았습니다. 현재는 실행 검증을 마친 faster-whisper를 사용합니다. [BitNet 모델 카드](https://huggingface.co/microsoft/VibeVoice-ASR-BitNet), [Windows 빌드 안내](https://github.com/microsoft/VibeASR.cpp#notes-for-windows)

## 녹음 날짜 결정

- WAV BWF의 origination date/time, 컨테이너·스트림의 `creation_time`, QuickTime creationdate, recording date, ID3 TDRC/date 태그 등을 우선 확인합니다.
- UTC 및 시간대가 있는 값은 `Asia/Seoul`로 변환합니다. 예: `2026-09-07T18:30:45Z` → `2026-09-08 03:30:45`.
- 시간대가 없는 값은 한국 시간으로 해석합니다. 날짜만 있으면 00:00:00을 사용하며 화면에 `※`와 설명을 표시합니다. 연도만 있는 태그는 녹음 날짜로 채택하지 않습니다.
- 읽을 수 있는 내부 날짜가 없으면 Windows 파일 생성 시각을 사용합니다. 복사·다운로드 과정에서 바뀐 시각일 수 있으므로 `※`를 표시합니다. 파일명에서 날짜를 임의 추측하지 않습니다.
- 사용한 날짜와 출처, 원본 태그, SHA-256, 모델 설정과 처리 상태는 `metadata.json`에 저장합니다. 날짜 열에 마우스를 올리면 출처와 대체 사유를 볼 수 있습니다.

메타데이터 자체가 실제 녹음 시작 시간을 보장하지는 않습니다. 일부 기기는 저장·인코딩 시각을 기록합니다.

## 긴 녹음과 작업 제어

오디오를 스트리밍으로 디코딩하고 약 5분 단위로 전사합니다. 구간 끝부분의 조용한 지점에서 가능한 한 나누며, 샘플을 버리거나 중복하지 않습니다. 조용한 지점이 없으면 경계에 걸친 단어의 정확도가 낮아질 수 있습니다. 파일 전체를 메모리에 올리지 않아 여러 시간의 녹음도 메모리 사용량을 제한합니다.

**대기열 일시정지**는 현재 작업을 마친 뒤 멈춥니다. **현재 작업 중단**은 GPU 프로세스를 종료하고 대기열도 멈춥니다. **대기열 계속**으로 다음 파일을 처리할 수 있습니다. 실패·중단한 항목은 선택 후 **다시 시도**할 수 있으며, 처음부터 새 폴더에서 전사합니다. 부분 전사 지점부터 이어 쓰지는 않습니다.

전사 중에는 `.partial.txt`, 복사 중에는 `.copying` 파일을 사용합니다. 성공했을 때만 최종 TXT 이름으로 바꿉니다. 실패해도 원본과 복사본·임시 전사본은 보존합니다. 작업 기록과 설정은 `state/session.json`, 마지막 작업 프로세스 로그는 `state/worker.log`에 있습니다. 앱을 닫거나 PC를 재시작하면 처리 중이던 항목은 중단으로 표시됩니다. 대기 항목은 자동 시작이 켜져 있으면 앱 재실행 시 처리됩니다.

모델·참고 용어·저장 위치 설정은 **새로 추가하는 파일**에 적용됩니다. 참고 용어에는 이름, 회사명, 제품명 등을 넣을 수 있으며 정확한 표기를 보장하지는 않습니다. TXT 시간 표시는 초 단위의 대략적인 구간입니다.

화자 구분은 아래 준비 절차 후 사용할 수 있습니다. 회의 요약은 포함하지 않습니다. 겹말, 낮은 음량, 잡음, 고유명사는 실제 녹음에서 확인이 필요합니다.

## 화자 구분 준비와 사용

`install.cmd`는 화자 분석용 **별도 Python 환경과 PyTorch CUDA**를 설치합니다. Community-1 모델은 Hugging Face 계정으로 접근 조건을 수락한 뒤 다운로드해야 합니다.

1. 앱의 **모델 준비**를 누릅니다.
2. [Hugging Face 가입](https://huggingface.co/join) 후 이메일을 확인합니다.
3. [Community-1 모델 페이지](https://huggingface.co/pyannote/speaker-diarization-community-1)에서 접근 조건에 동의합니다. 조건에는 연락처 공유와 안내 메일 동의가 포함되어 있으므로 해당 페이지에서 직접 확인합니다.
4. [토큰 설정](https://huggingface.co/settings/tokens)에서 **Read(읽기)** 권한 토큰을 만듭니다. 쓰기 권한은 필요하지 않습니다. Fine-grained를 사용한다면 해당 모델을 다운로드할 수 있는 읽기 권한이 필요합니다.
5. 앱의 마스킹된 입력란에 토큰을 붙여넣고 **모델 다운로드 및 확인**을 누릅니다. 토큰은 채팅에 보내지 않습니다.

다운로드와 로컬 모델 로딩·GPU 확인이 성공해야 준비 완료로 표시합니다. 토큰은 프로세스의 표준 입력으로만 전달하고 앱 설정·작업 JSON·로그·명령행 인자에 저장하지 않습니다. 다운로드가 끝나면 이후에는 로컬 모델 경로만 사용하며, 화자 분석 프로세스에서 Hugging Face 오프라인 모드와 pyannote 통계 전송 끄기를 적용합니다. 로컬 Community-1 분석에는 건당 API 비용이 없습니다. [모델 사용법](https://huggingface.co/pyannote/speaker-diarization-community-1), [토큰 권한 설명](https://huggingface.co/docs/hub/security-tokens)

**계정이 없어도 일반 전사는 사용할 수 있습니다.** 화자 구분을 켜고 파일을 추가하면 일반 TXT와 단어 시간 JSON을 먼저 저장합니다. 모델이 없을 때는 목록에 **준비 필요**를 표시합니다. 나중에 모델 준비를 마친 뒤 해당 행을 선택하고 **화자 분석 / 재시도**를 누르면 전사를 반복하거나 새 폴더를 만들지 않고 화자 분석만 실행합니다.

- **화자 구분 사용**: 새로 추가하는 파일에 적용합니다.
- **참석자 수**: 기본 자동. 알고 있으면 1~30명 중 지정할 수 있습니다.
- **화자 분석 · GPU / CPU**: 기본 GPU. GPU 메모리가 부족하면 CPU로 변경한 뒤 화자 분석만 다시 시도할 수 있습니다. 일반 전사는 계속 GPU를 사용합니다.
- **화자 이름 변경**: 분석 완료 후 `화자 1` 등을 실제 이름으로 바꾸면 TXT가 즉시 다시 저장됩니다. 이름은 해당 녹음 안에서만 적용됩니다.
- **현재 작업 중단**: 진행 중인 전사 또는 화자 분석 프로세스를 종료하고 대기열을 멈춥니다. 화자 분석 중 중단한 경우 일반 전사본은 남습니다.

```text
2026-09-08_03-30-45_주간회의/
  주간회의.m4a          원본 복사본
  주간회의.txt          최종 화자 표시 전사본
  주간회의.plain.txt    화자 표시 전 일반 전사본
  transcript.json      단어 시간과 전사 원문
  speakers.json        화자 구간, 표시 이름, 연결된 발언
  metadata.json        날짜 출처와 단계별 상태
```

Whisper 프로세스가 완전히 종료된 뒤 화자 분석 프로세스를 시작합니다. 전사는 약 5분씩 처리하지만 **화자 분석은 파일 전체를 한 번에 묶어** 같은 화자가 구간마다 다른 번호가 되는 문제를 피합니다. 오디오는 디스크에 임시 float 버퍼로 디코딩한 뒤 메모리 매핑하여 큰 배열을 두 번 복사하지 않습니다. 다만 pyannote의 분석 중간값과 운영체제 파일 캐시에는 녹음 길이에 비례하는 RAM이 필요합니다. 메모리 사용량이 녹음 길이와 무관하게 일정하다는 의미는 아닙니다. 임시 버퍼는 정상 종료 시 제거하고 강제 중단 뒤에는 같은 항목의 재시도에서 다시 씁니다.

단어 시간과 단일 화자 구간을 대조하여 줄을 나눕니다. 실제 동시 발화가 감지되면 `[겹말]`, 시간 배정이 애매하면 `[확인 필요]`, 대응되는 화자가 없으면 `화자 미확인`을 표시합니다. 표시된 불확실성은 시간 대응을 기준으로 한 보조 표시이며 모델이 제공한 신뢰도 점수는 아닙니다. 겹친 음성을 각각 복원하는 음원 분리나 파일 간 인물 자동 인식은 포함하지 않습니다.

구버전에서 만든 결과에 `transcript.json`이 없다면 파일을 다시 추가해 단어 시간을 포함한 전사를 한 번 만들어야 합니다. 재분석하면 기본 화자 번호부터 다시 결정되므로 기존에 지정한 화자 이름도 다시 확인해야 합니다.

화자 환경을 재설치할 때는 다음을 실행합니다. 모델 다운로드는 이후 앱에서 진행합니다.

```powershell
.\setup-diarization.ps1
.\.venv-diarization\Scripts\python.exe -X utf8 -m meeting_stt.diagnose_diarization
```

PyTorch 2.8.0 CUDA 12.8 / torchaudio 2.8.0 / pyannote.audio 4.0.7을 사용합니다. 오디오는 기존 PyAV로 읽어 텐서로 전달하므로 TorchCodec의 별도 FFmpeg DLL에 의존하지 않습니다. 설치 스크립트는 검증된 버전을 담은 `requirements-diarization.lock.txt`를 사용합니다.

## 설치와 점검

처음 설치할 때는 위의 `install.cmd`를 사용합니다. 전사 환경만 설치하거나 재점검할 때는 uv 또는 Python 3.11과 NVIDIA 드라이버가 있는 Windows에서 다음을 실행합니다.

```powershell
.\setup.ps1
```

`setup.ps1`은 이 PC에서 검증한 버전을 담은 `requirements.lock.txt`를 사용합니다. CUDA의 cuBLAS/cuDNN DLL은 가상환경에 설치하며, 실행 프로세스의 DLL 검색 경로에만 추가합니다. 시스템 PATH나 다른 Python 환경은 변경하지 않습니다. FFmpeg 실행 파일은 일반 사용에 필요하지 않습니다. PyAV가 디코딩과 메타데이터 읽기를 담당합니다.

모델은 `models/large-v3`, `models/turbo`에 저장합니다. 모델 준비가 완료된 이후에는 해당 모델을 네트워크 요청 없이 직접 읽습니다. 모델 다운로드에만 Hugging Face를 사용하며 녹음·전사 내용은 전송하지 않습니다.

```powershell
# GPU 인식 및 지원 연산 확인
.\.venv\Scripts\python.exe -m meeting_stt.diagnose

# 자동 테스트
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v

# 일반 전사 파이프라인을 명령행에서 실행 (화자 분석은 GUI에서 설정)
.\.venv\Scripts\python.exe -m meeting_stt.cli "C:\recordings\회의.m4a" --model large-v3
```

GPU 메모리가 부족하면 다른 GPU 앱을 닫거나 Turbo를 선택해 다시 시도합니다. GPU 문제가 발생했을 때 CPU로 조용히 전환하지 않고 화면에 오류를 표시합니다.

## 검증 결과

2026-09-08, 이 PC의 RTX 3050 6GB에서 확인했습니다.

- 기본 환경의 자동 테스트 29개 통과. 선택 환경 테스트 2개는 기본 환경에서 건너뛰고, 화자 분석 환경에서 따로 실행하여 통과했습니다. 날짜·복사·중단·대기열 외에 프로세스 분리, 모델 준비 전 처리, 화자 단계만 재시도, 이름 수정과 TXT 재생성, 토큰 오류 메시지 마스킹, 완료 이벤트 유실 시 저장 결과 복구를 포함합니다.
- 초기 버전에서 Windows의 Microsoft Heami 음성으로 만든 한국어 샘플 18.6초를 실제 GPU에서 전사했습니다. Large v3는 10.14초, Turbo는 5.03초가 걸렸습니다. 단어 시간 저장을 추가한 뒤 같은 Turbo 샘플을 다시 실행해 24개 단어 시간과 전사 JSON 저장을 확인했고 이 실행은 8.19초였습니다. 모델 로딩을 포함한 개별 실행이며, 모델 본체는 미리 다운로드된 상태였습니다. 통제된 성능 벤치마크가 아닙니다.
- 두 모델 모두 샘플의 세 문장과 날짜·시각·예산 수치를 인식했습니다. 이는 합성 음성 기능 확인이며 실제 회의 인식률을 측정한 결과는 아닙니다.
- GUI의 파일 선택 → 전사 완료 → 날짜 폴더/TXT 저장 흐름을 실제 창에서 확인했습니다.
- 입력 M4A와 저장한 M4A의 SHA-256이 일치했습니다.
- 화자 분석 환경에서 pyannote import와 실제 CUDA 합성곱 연산이 성공했습니다. 2026-09-09에는 Community-1 모델 준비 완료 상태도 확인했습니다. **실제 다중 화자 회의의 정확도·VRAM 사용량은 별도 측정하지 않았습니다.**
- 1시간 오디오의 디코딩·전역 입력·화자 연결·내보내기는 고정된 화자 구간을 반환하는 테스트 파이프라인으로 검증했습니다. 실제 다중 화자 회의의 품질 검증을 대체하지 않습니다.
- 인터넷 오프라인 모드에서 실제 Whisper GPU 전사와 GUI 대기열을 연결하여, 단어 시간 24개와 TXT를 저장하고 모델 없는 화자 단계만 `준비 필요`로 남기는 전체 흐름을 확인했습니다.

개발 PC의 테스트 샘플, 녹음 파일과 출력 결과는 공개 저장소에 포함하지 않습니다. 자동 테스트는 임시 합성 데이터를 사용합니다.
